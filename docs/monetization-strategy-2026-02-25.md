## 종합 결론

### 전원 일치 의견 (6/6 동의)

**1. "레시피를 팔지 말고, 장보기 리스트를 팔아라"**
- 레시피는 트래픽 미끼, 수익은 식재료 커머스 (쿠팡 파트너스)
- 사용자 비용 $0인 유일한 수익 모델 → 거부감 제로
- 이미 `CoupangLinkService` 구현됨 → 전환율 최적화만 하면 즉시 수익

**2. "3단계 품질 차등 프리미엄은 실패한다"**
- "번개로 해봤는데 별로니까 정밀로?" — 이 사고가 자연스럽지 않음
- "품질 차등은 사용자를 적으로 만든다"
- 대안: 품질이 아닌 **편의**로 차등화 (주간 식단, 냉장고 관리 등)

**3. "아직 유료화할 때가 아니다"**
- "매주 돌아오는 100명을 먼저 만들어라"
- 트랙션 데이터 없이 구독 모델은 의미 없음
- 무료로 사용자 모으기 → 쿠팡 제휴로 서버비 충당 → 기반 확보 후 프리미엄

## 권장 수익화 로드맵

### Phase 1: 생존 (0-3개월) — "서버비라도 벌자"

1. **쿠팡 파트너스 최적화** — 장보기 리스트 UX 개선, 전환율 측정
2. **이미지 비용 차등화** — 비로그인: 이미지 없음, 로그인: Google Image, 프리미엄: Gemini
3. **커뮤니티 시딩** — 에브리타임, 자취 카페, 인스타 릴스 (예산 0원)
4. **SEO** — 인기 재료 조합 정적 페이지 생성
- **목표**: WAU 500, 쿠팡 수수료로 월 10-20만원

### Phase 2: PMF 탐색 (3-6개월) — "매주 돌아오는 이유 만들기"

1. **주간 식단 플래너 MVP** — 이것이 구독 핵심 가치

### Phase 3: 수익화 (6-12개월) — "돈 낼 만한 이유"

## CEO 분석: 비즈니스 전략

### 시장 포지셔닝 — USP는 존재하는가?

**솔직한 평가: "얇은 USP"**

GPT 대비 이 서비스가 제공하는 것:
- **구조화된 출력**: 레시피 3개 + 장보기 리스트 + 이미지 + 보유/미보유 재료 분리를 원클릭 제공
- **반복 사용의 편의**: 재료 저장, 검색 기록, 즐겨찾기, 쇼핑몰 연동
- **한국 특화**: 한국 계량("큰술"), 한국 재료 동의어("파/대파/쪽파"), 한국 요리 용어

**그러나 현실은:**
- 이 가치들은 "Nice to have"이지 "Must have"가 아니다
- GPT에게 비슷한 프롬프트를 쓰면 80% 비슷한 결과
- **진짜 USP는 "마찰 제거"** — GPT를 열고 프롬프트를 쓰고 결과를 해석하는 인지적 부담 vs 앱 열고 재료 태그 입력 → 버튼 한번

> **기능적 해자는 거의 없다.** USP는 "사용자 경험의 간결함"과 "한국 요리 특화 워크플로우"에 있다.

### 수익 모델 제안

| 모델 | 현실성 | 설명 |
|------|--------|------|
| **A. 장보기 커머스** | ★★★★★ | 쿠팡 파트너스 3-7% 수수료. DAU 500 기준 월 ~50만원. 서버비 커버 가능 |
| **B. 식재료 구독 박스 제휴** | ★★★☆☆ | 마켓컬리, 정육각 등과 CPA/CPS 제휴 |
| **C. B2B/화이트라벨** | ★★☆☆☆ | 식품 기업(CJ, 풀무원)에 API 판매 |
| **D. 편의 차등 프리미엄** | ★★★☆☆ | 월 2,900원 — 무제한, 광고 제거, 주간 식단 자동 생성 |

### 경쟁 우위 지속 가능성

| 요소 | 방어력 | 이유 |
|------|--------|------|
| LLM 레시피 생성 | ❌ 없음 | 누구나 GPT API로 가능 |

**유일한 해자는 "사용자 데이터 + 습관":**
1. 개인화 데이터 축적 → "내 냉장고를 아는 앱"
2. 네트워크 효과 — 사용자 레시피 공유/평가 → 데이터 품질 상승
3. 습관 루프 — 퇴근 → 앱 열기 → 재료 입력 → 요리

## CTO 분석: 기술/확장성

### 기술적 해자 — 솔직한 평가

**해자 강도: 3/10 (현재) → 7/10 (데이터 축적 후)**

해자가 약한 부분:
- LLM 래퍼 구조 — 경쟁자가 동일 API로 비슷한 품질 달성 가능
- 이미지 생성 — 누구나 같은 방법 사용 가능
- 프론트엔드 — 표준 Next.js 구현

해자가 존재하는 부분 (중간 수준):
1. 재료 동의어 + 역색인 시스템 — O(m) 카테고리별 매칭
2. 3단계 품질 파이프라인 — 다층 구조 복제에 시간 필요
3. 검증 파이프라인 — hard/soft 검증, 경험에서 나온 것
4. SHA256 기반 캐시 — 동의어 정규화 + hit_count 추적

### 데이터를 해자로 만드는 전략

**A. 레시피 피드백 루프 (핵심)**
```
사용자 입력 → LLM 생성 → 사용자 평가 → 데이터 축적 → 품질 향상
```
- 현재 별점/평가 없음 — 가장 큰 데이터 약점
- 고평가 레시피를 reference_recipes에 자동 승격 → LLM 의존도 점진적 감소

**B. 재료 동의어 자동 확장** — 사용자 입력 로그에서 미등록 동의어 발견

**C. 인기 재료 조합 프리캐싱** — recipe_cache hit_count 기반

### LLM 비용 10배 절감 방안

1. **캐시 적중률 극대화** (즉시) — fuzzy 캐시 + TOP 100 프리캐싱 → 5-10배
2. **경량 모델 계층화** (중기) — standard도 Haiku로 대체, 템플릿 매칭+변형
3. **파인튜닝** (장기) — 고평가 5,000개 축적 후 경량 모델 파인튜닝 → 비용 ~$0
4. **CLI → API 전환** — subprocess 오버헤드 제거, 스트리밍 가능

## CPO 분석: 제품/UX 전략

### PMF 진단

**현재: PMF 이전 단계 (Pre-PMF)**

PMF가 없는 이유:
- 리텐션 메커니즘 부족 — 1-2회 써보고 떠날 가능성
- 다시 돌아올 이유(재방문 트리거)가 약함
- 핵심 경험이 "1회성 조회"에 머무름

PMF를 찾을 수 있는 방향:

| 방향 | PMF 신호 |
|------|----------|
| 주간 식단 플래너 | 주 1회 이상 재방문 |
| 냉장고 재료 관리 (유통기한 알림) | 매일 앱을 여는 습관 |
| 가계부 연동 (예산 기반 추천) | 경제적 가치 체감 |
| 커뮤니티 (인증샷) | 사용자 생성 콘텐츠 |

> **핵심 인사이트: 앱의 가치는 "레시피 생성"이 아니라 "뭐 해먹지? 고민 해결"**

### 유료 기능 설계 — "돈 내도 되겠다" 순간

**원칙: "무료 사용자도 충분히 좋은 레시피를 받아야 한다. 유료는 더 많이, 더 편하게."**

**Tier 1: 프리미엄 편의 기능 (월 2,900원)**
- 주간 식단 자동 생성 (GPT한테 물어보기 어려운 것)
- 냉장고 재료 관리 (사진 AI 인식 + 유통기한)
- 영양 목표 추적
- 진정한 무제한 검색

**Tier 2: 1회성 프리미엄 (건당 500원 / 쿠팡 구매 시 무료)**
- 밀프렙 가이드 (3일치 한번에)
- 손님 접대 모드 (4-6인 코스 구성)

### 페이월 UX

**하면 안 되는 것:**
- ❌ 레시피 3개 중 1개 흐리게 처리
- ❌ fast에서 의도적으로 이미지 제거
- ❌ 결과 페이지 갑자기 팝업

**추천 패턴:**
- "아하" 모먼트 이후 제안 (3번째 검색 완료 후 → 주간 식단 무료 체험 안내)
- 가치 체감 후 넛지 (장보기 예상 비용 표시 → 예산 맞춤 추천 안내)
- 자연스러운 상향 판매 (레시피 하단 → 밀프렙 가이드 안내)
- 제한 도달 시 부드러운 안내 (절대 "구독하세요" 아닌 "이런 옵션도 있어요" 톤)

### 기능 우선순위 Top 5

| 순위 | 기능 | 수익 기여 | 이유 |
|------|------|-----------|------|
| 1 | 주간 식단 플래너 | ★★★★★ | PMF + 유료화 핵심 |
| 2 | 냉장고 재료 관리 | ★★★★☆ | 리텐션 극대화 |
| 3 | 쿠팡 파트너스 딥링크 최적화 | ★★★★☆ | 즉시 수익, 이미 구현됨 |
| 4 | 밀프렙 모드 | ★★★☆☆ | 자취생 핵심 니즈, 건당 결제 |
| 5 | 소셜 기능 (인증샷/공유) | ★★☆☆☆ | 바이럴 성장 |

### GPT 대비 UX 차별점

| 항목 | ChatGPT | 오머먹 |
|------|---------|--------|
| 응답 형태 | 텍스트 덩어리 | 구조화된 카드 |
| 재료 매칭 | 없음 | 보유/추가 자동 분류 |
| 장보기 리스트 | 없음 | 자동 생성 + 구매 링크 |
| 이미지 | 없음 | AI 자동 생성 |
| 공유 | 링크 복사 | 카카오톡 피드 |
| 기록 | 채팅에 묻힘 | 전용 기록 + 즐겨찾기 |

### 사용자 여정 퍼널

```
방문 → 첫 레시피 → WOW → 회원가입 → 반복 사용 → 유료 전환
100%     70%       60%     30%       15%         5%
```

핵심 최적화:
- Stage 1: 기본 재료 프리셋 ("자취생 기본 세트" 버튼)
- Stage 2: WOW = "이거 진짜 해먹을 수 있겠다" + 소셜 프루프
- Stage 3: 2회째 검색 후 "기록 저장" 넛지, 카카오 1-click 로그인
- Stage 4: 월요일 오후 5시 알림 → 주간 식단 → 통합 장보기 → 쿠팡 구매
- Stage 5: 4주 연속 사용자에게만 프리미엄 제안

## 사용자 페르소나 피드백 (김민수, 25세 서울 자취생)

### 프로필
- 월급 세후 230만원, 월세 50만원, 식비 40-50만원
- 구독: 넷플릭스 + 유튜브 프리미엄 = 28,400원
- 특징: 가성비 중시, 구독 피로감, "또 결제?"에 민감

### 첫인상
"오, 쓸만하겠는데?" 쪽에 가까움. GPT보다 구조화된 출력이 편해 보임.
단, "이걸 위해 새 앱을 깔아야 하나?" 허들 있음 (웹앱이라 설치 불필요한 건 좋음)

### 현실적 사용 빈도
주 2-3회. 초반 매일 → 2-3주 후 주 2회 수렴 → 한 달 뒤 주 1회 가능성

### 결제 의향 (5가지 모델)

| 모델 | 결제 의향 | 이유 |
|------|-----------|------|
| 배너 광고 | ✅ 수용 | 결과 페이지 하단 OK. 전면 광고는 2주 내 이탈 |
| 월 구독 (₩3,900) | ❌ 안 낼 확률 높음 | "또 구독?" 구독 피로감 |
| 횟수 제한 (3회/일) | ⚠️ 결제 안 함 | 일 3회면 충분해서 제한에 걸릴 일 없음 |
| 1회 구매 (₩1,000) | ❌ 거의 안 삼 | 영양정보/AI이미지에 1,000원 가치 못 느낌 |
| 쿠팡 제휴 | ✅ 최고 | 추가 비용 0원, 거부감 제로 |

### 가격 민감도
- 월 구독 최대 2,900원, 1회 구매 최대 500-1,000원
- 그 이상이면 "그냥 GPT한테 물어볼까" 이동

### 이탈 포인트
1. 레시피가 맛없을 때 (가장 치명적)
2. 같은 레시피 반복
3. 전면 광고 or 강제 회원가입
4. 장보기 리스트가 현실과 안 맞을 때
5. 로딩 5초 이상
6. 요리 자체를 안 하게 됐을 때

### 킬러 기능 ("이게 되면 돈 내도 된다")
1. **냉장고 사진 → 재료 자동 인식** — "미쳤다고 할 듯"
2. **3분 요약 영상** — 텍스트 조리 단계의 한계 극복
3. **주간 식단 + 통합 장보기** — "이거 되면 구독 고려"
4. **남은 재료 추적** — 음식물 쓰레기 줄이기
5. **자취생 인기 레시피 랭킹** — 동기부여

추천 멘트: *"야 이거 재료 넣으면 레시피 알려주는 건데, 한 번 해봐. **무료야**."*
